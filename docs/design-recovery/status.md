# Design recovery status

Date: 3 August 2026  
Status: exploration authorized; presentation implementation not authorized

## Decision

The current Forecast Journey React application is an engineering baseline and an unapproved presentation candidate. The user explicitly rejected its rendered design and UI/UX as the final direction. Previous repository language that called the implementation or its exploratory vectors "approved" was unsupported and is revoked.

Passing unit tests, browser checks, accessibility automation, Impeccable Doctor, or the detector does not confer visual approval.

## Preserve during exploration

- deterministic PK/effect-site behavior and tests;
- schedule domain types and validation;
- derived-heuristic boundaries and medical semantics;
- local-first privacy and static GitHub Pages deployment;
- editing, import, export, and sharing behavior unless a separate correctness defect is evidenced;
- synthetic fixtures and the automated verification matrix;
- separation between My Day and Analyze as audience/product intent, while allowing their navigation and screen structure to be redesigned.

## Reopened for design

- first-viewport hierarchy;
- relationship among current context, next dose, day overview, and journey;
- navigation and Schedule entry;
- information density and disclosure sequence;
- visual world, typography, color strategy, iconography, shape, material, and container use;
- responsive composition for phone landscape, tablet, and desktop;
- patient-facing terminology where it overstates a schedule-relative model;
- editor structure and presentation while preserving validated behavior.

## Required route

1. Intent evaluation of goal fit, comprehension, task sequence, cognition, motor demands, and semantic honesty.
2. Screenshot-grounded rendered critique, separately owned by Product Design and Impeccable craft lenses.
3. Journey, Organize, Include, and Wireframe remediation of routed structural findings.
4. Three genuinely different, comparable high-fidelity phone directions using the same synthetic content and core state.
5. Explicit user selection or requested revision.
6. Only then: implementation specification, implementation branch, rendered comparison, verification, and pull request.

## Approval record

No replacement direction is approved yet. Future approval must identify the rendered artifact or Figma frame selected by the user and the date of the decision. Silence, automated success, merge status, or an agent-authored `passed` line is not approval.
